# 插图工具（常规版）

本工具由具有生图能力的外部 Agent 执行。用户提供小说、章节或章节中的剧情片段，以及希望采用的画面风格。**默认交付一组按剧情推进的连续插图，不以生成一张图作为任务完成。**先为整段剧情规划镜头，再逐张生成和插入；若用户指定数量、插入位置或角色形象，以用户要求为准。只有用户明确要求单张，或目标片段确实只有一个可画瞬间时，才只生成一张。当前只生成静态图片；不执行视频生成。

## 关联工具

- [创作工具的空间操作](../creation/workspace.md)：`index`、`read`、`search`、`character.read`、`character.assets`、`illustration.references`、`illustration.add`。
- [创作工具的上下文操作](../creation/context.md)：按需读取本书约束、有关技能和素材；不要整库加载。
- [连续插图提示词模板](prompt-template.md)：先规划整组镜头与连续性锚点，再逐张填写；不将多个先后发生的动作压进同一张图。
- [设计依据](research.md)：图像生成文档、视觉叙事研究与本工具的取舍。

## 输入定位与上下文

1. 确定小说的绝对目录。调用创作工具的空间操作 `index` 找到章节和正文文件；用户给出一段剧情时，用 `search` 定位到对应章节，再用 `read` 完整读取正文，确定插入位置。找不到唯一位置时，结合章节标题、相邻段落和用户用语继续定位；仍不明确才询问用户。
2. 阅读目标片段和必要的前后文，将剧情按时间顺序拆成若干有画面价值的节拍。先列出整组镜头：序号、对应段落、当前关键动作或情绪转折、人物表情与道具状态、场景位置、景别与机位、计划插入点。优先抓住能改变人物关系、动作结果或情绪的瞬间，留意视线、眉眼、嘴角、手势和身体重心等有正文依据的细节；让相邻镜头呈现情绪如何变化，不凭空添加正文没有的反应。数量由剧情节拍决定，不预设固定张数，也不为了凑数重复同一瞬间；整章任务应覆盖关键起因、推进和结果。每张图只呈现**一个瞬间**，相邻图片可以从不同时间点和机位共同表现动作的先后。不要为了插图而改写剧情。
3. 对本次场景，在前文章节中用 `search` 查场景名、别名和关键物件。对相关章节调用 `illustration.references`，获得已引用插图的绝对路径和邻近正文。把与当前场景对应的已保存图片作为场景参考输入给生图工具；没有既有图片时，以已确认的场景文字为准。尤其注意同一建筑的空间布局、陈设和色彩。
4. 对出场角色调用 `character.read` 获取脸部身材、设定及全部形象的 ID 和文本描述，再调用 `character.assets` 获取各形象的资产图绝对路径。**有多套形象时，先判定这一剧情瞬间穿着或呈现哪一套**：读目标段落及同场景较早段落的形象、换装和形态描写；仍不明确时查剧情时间上最近的前文章节正文，再参考已提交的章末状态、接续包和旧插图。将这些文字线索与每套形象的文本描述比对；当前正文明确写出的变化优先于旧记录或旧图。逐镜头记下选定的形象 ID、名称及正文依据。若正文出现已有资产都不匹配的新形象，先说明缺少对应资产并按任务范围补建；没有任何可确认的形象依据时再向用户确认，不凭资产列表顺序猜选。
5. 为每个出镜角色、每一镜分别确定**面部锚点**和**服装锚点**。面部锚点优先用当前形象的脸部特写；若当前形象没有，可用同一角色其他形象的特写，但只固定五官和脸型。服装锚点必须来自当前选定 `appearanceId` 的全身、上半身或下半身定妆资产，并结合该形象的文本描述固定衣服的版型、层次、颜色、纹样及配饰；不能让脸部特写或其他形象的衣服决定本帧服装。用可用的图片查看能力确认所选资产实际展示了哪些身体和服装部位，不能仅凭文件名把下半身图标成全身图；只覆盖局部时据实注明，并按需合用同形象的其他局部资产。若没有可用的服装资产，以当前形象文本描述为依据并明确缺少图片参考，不借用其他形象的服装。这里确认的是**输入资产与用途**，不要求 Agent 验收生成图片的质量。
   **星离的强制规则：只要生成或编辑后的图片包含慕星离，每一次模型调用都必须实际传入当前剧情所选 `appearanceId` 对应形象的脸部特写图片。首次文生图、连续插图生成、局部重绘和成图后的任何图片编辑均适用，即使本次只改背景、服装或特效也不能省略。文字描述、上一张成图及其他形象的脸部特写都不能代替它。当前形象缺少脸部特写，或所用模型接口无法传入该图时，停止这次生成或编辑并说明原因，不降级为仅传文字。**
6. 为整组镜头建立连续性记录：角色当前形象 ID、站位与朝向，手中道具、伤势、衣物和发型状态，场景布局与损坏情况，光源和时间。每个镜头从上一镜头继承仍然有效的状态；正文在两帧之间明确换装或改变形态时，从变化发生后的镜头起切换形象 ID 和资产参考。跨章节沿用相关前文插图和角色资产，不因新镜头重新发明场景或人物。

## 场景建立图

将目标剧情按实际地点、空间和时间变化划分为场景段。**每进入一个新的场景段，先规划、生成并插入一张纯场景建立图，再制作该场景的人物和动作插图**；目标片段开头进入场景、离开后重新进入场景时也适用。跨章节连续处于同一场景、且已有可用建立图时不重复生成。同一场景内连续镜头也不重复生成。若用户指定总张数，将建立图计入总数；数量不足以覆盖必需的场景与关键剧情时，先说明取舍并请用户调整数量。

建立图只展示后续几张插图共同使用的主要背景：地点的空间结构、前后左右关系、关键建筑或陈设、光源、时间和天气。画面**不能出现人物、剪影、倒影中的人、背景人群或角色身体部位**；不把人物动作、战斗特效或之后才发生的破坏提前画进去。先用前文场景图与正文核对环境，再选能交代主要空间的景别和机位。建立图生成后，把它作为该场景随后每张人物插图的场景参考图输入；角色面部和服装仍分别使用当前形象资产。剧情明确改变环境时，后续镜头只在这个基础上更新变化，不能无故换背景。

## 设计与生成

1. 先按 [连续插图提示词模板](prompt-template.md) 填完整组镜头计划和共享视觉锚点，再为每一镜填写场景卡与生图提示词。明确这一镜相对于上一镜发生了什么、哪些状态延续、哪些状态由剧情改变；人物姿态、视线、距离、表情和空间位置要能传达当前事件与情绪。按叙事重点灵活选择景别和机位：特写突出关键表情、手势或物件，近景兼顾人物反应与动作，中景交代人物关系及动作方向，必要时用远景建立空间。可在连续插图中切换机位和时间点，但每次切换应服务于新的信息或情绪变化，并保持人物站位、动作方向与场景布局可辨；不要机械轮换景别，也不要把多个时间点拼在一张图里。
2. 根据主体与空间关系选择合适的画幅方向及生图工具支持的最接近比例。不要统一固定图片尺寸或先裁剪到某一比例；以主要画面完整、细节清晰为先。生图工具有限定比例时，选择最适合构图的一项并保留必要留白。
3. 画面保持清楚的视觉主次，减少无关人物、杂物、文字、水印和脏乱噪声。战斗场面要充分表现本次动作的法术、冲击、气流、光效和环境反应，同时让人物及关键动作可辨；不要把起手、命中、倒地等先后事件拼在同一张图，也不要用多格漫画代替单帧插图。
4. 按镜头顺序使用外部 Agent 当前可用的生图能力。每张都传入适用的角色资产与场景参考：对每个出镜角色，脸部特写存在时重复传入面部锚点，当前形象有服装资产时也重复传入服装锚点，并在提示词中分别标明每张参考图的角色、形象 ID、实际覆盖部位和用途；不能只传脸图却要求模型自行还原整套衣服。从第二张起，再把上一张已生成图片作为连续性参考，并明确哪些元素保持、哪些变化。上一张插图只用于连续性，不能代替面部或服装锚点；与已确认角色资产或正文冲突时，以当前形象资产和正文为准。不能使用必要参考图或不能产出本地 PNG 时，说明具体缺少的能力并保留整组镜头提示词；不要声称已生成或已插入。

## 插入正文

1. 生图工具产出本地 PNG 绝对路径后，通过创作工具的空间操作 `read` 再读取目标正文，取得最新 `sha256`。按该次返回的 `content` 计算插入位置：`offset` 是 JavaScript 字符串索引，和 Node.js `indexOf` / `slice` 一致。场景建立图应放在进入该场景的文字之后、该场景第一张人物或动作插图之前；其余图片应放在所描绘段落之后。用户指定精确位置时优先遵守，并确保建立图仍先于该场景的人物镜头。
2. 调用 `illustration.add`，传入 `chapterCardId`、本地 `imagePath`、正文 `expectedSha256` 和 `offset`。该接口会验证文件、按现有顺序生成 `001.png` 等名字，并以一次事务写入章节的 `images/` 文件和 `![](images/001.png)` 正文引用。不要自行复制进章节目录或手改引用来绕过接口。
3. 每生成一张就按镜头顺序插入其剧情段落之后，再重新 `read` 获取新内容与哈希，定位下一张的插入点。不能沿用上一张的 offset 或哈希；接口提示正文已更新时重新定位后再试，避免重复插入。写入后调用 `read` 和 `illustration.references` 核对整组引用的顺序、路径和位置。这里只核对文件与正文结果，不要求 Agent 主观检查成图质量。
4. 向用户按剧情顺序报告整组镜头、章节段落、图片绝对路径和风格，并说明哪些已插入、哪些因能力或调用错误未完成。用户未要求修改剧情文字时，不修改剧情文字。

## 工具调用示例

```json
{"action":"illustration.references","input":{"chapterCardId":"从 index 取得的章节 ID"}}
```

```json
{"action":"character.assets","input":{"characterId":"从 index 取得的角色 ID"}}
```

```json
{"action":"illustration.add","input":{"chapterCardId":"从 index 取得的章节 ID","imagePath":"/生成图片的绝对路径/scene.png","expectedSha256":"read 返回的 sha256","offset":1234}}
```

需要移除误插入的图片时，先用 `read` 取得最新正文哈希，再用 `illustration.references` 确认图片文件名和引用位置；调用 `illustration.delete` 并传入 `chapterCardId`、`filename`、`expectedSha256`、`offset`。同一图片还有其它引用时，只移除指定位置的引用。实际字段格式可用 `{"action":"schema","input":{"name":"illustration.add"}}` 或 `illustration.delete` 查询。调用 CLI 的方式见[创作工具的空间操作](../creation/workspace.md)。
