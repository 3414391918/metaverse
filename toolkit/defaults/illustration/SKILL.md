# 插图设计

本工具只负责**生成前的插图设计**。用户给出小说、章节或剧情片段及风格要求后，按剧情顺序逐张交付独立可用的插图物料：该张全部参考图的预览与绝对路径，以及完整生图提示词。镜头数量由剧情节拍决定；用户明确要求单张时可以只设计一张。**本工具不调用生图或修图能力，不审核生成后的图片，不插入、替换或删除正文图片。成图质量和审美由用户自行验证。**

## 关联工具

- [创作工具的空间操作](../creation/workspace.md)：用 `index`、`search`、`read` 定位和读取正文；用 `character.read`、`character.assets` 读取当前形象及原始角色资产；用 `illustration.references` 从本书正文引用查找纯场景图。这里只使用读取操作。
- [创作工具的上下文操作](../creation/context.md)：按需读取本书约束、有关技能和素材。
- [连续插图的逐张物料模板](prompt-template.md)：每张独立展示全部参考图片、绝对路径和自足的画面提示词。
- [设计依据](research.md)：提示词结构和视觉叙事的参考资料。

## 输入与主要人物确认

1. 确定小说及目标章节。用 `index`、`search`、`read` 找到目标剧情并完整读取正文，必要时读前后章节；不能仅凭用户描述猜测剧情位置。记录章节、段落锚点和用户指定的预期插图位置，但不写入正文。已入正文的插图以**本书该章节 `body.md` 中的 `![](images/文件名)` 引用及同级 `images/` 目录下的实际文件**为准；不要把其它目录中同名或近似命名的图片当作正文插图。
2. 列出目标剧情中可能出镜的人物，**在逐镜设计前请用户明确本轮哪些是主要人物，并等待回复**。主要人物由用户决定，不按主角身份、戏份或画面大小自行划定。若用户在本轮请求中已明确给出名单，可直接采用，不重复询问；未列入名单的出镜者视为非主要角色。
3. 用户指定画面风格时以其要求为准；未指定时从本书已有设定和插图推断并注明依据。缺少影响角色身份、当前形象或关键情节的事实时询问用户；不把推断写成既定设定。

## 剧情、场景与角色参考

1. 将目标片段按时间拆成有画面价值的节拍，覆盖关键起因、推进和结果。每张图只设计**一个剧情瞬间**；用特写、近景、中景、远景及不同机位表达关键动作、表情和情绪变化，不把先后动作画在一张图中。记录每镜的正文锚点、人物站位、朝向、伤势、道具和场景变化，后一镜继承仍有效的状态。
2. **先查目标章节，再查同一本书的相关前文章节**：用 `read` 在正文中找地点、别名、时间和光源变化，核对相邻的 `images/` 引用；对这些章节逐一调用 `illustration.references`，优先用 `query` 搜索地点、时段或图片文件名，默认从后往前返回 6 条，可用 `offset` 翻页。完整读取返回的 `path`、`nearbyText`、`available` 和 `hasMore`；不得用 `head` 截断 JSON 输出，也不得把首批未出现的图片判成不存在。从章节 `images/` 中定位适用的**无人纯场景图**。候选图可查看以确认它确实无人且符合本镜时段；这是参考图识别，不是对新生成图片作质量审核。**临时交付目录、候选稿目录和镜头计划不是正文图片来源，禁止将它们作为场景图检索范围或参考路径**。目标章节正文已有适用图片时，不得因为临时目录中找不到而报告缺图。其他章节的人物插图只可供 Agent 理解剧情与整理文字连续性，不得列为生图参考图。确无已入正文的适用纯场景图时，再设计一张建立图提示词并标记“待用户生成”；不得虚构路径或声称已生成。
3. 对每个出镜角色读取 `character.read` 与 `character.assets`，结合正文中的换装、形态变化和最近的剧情状态，逐镜确定当前 `appearanceId`。当前正文明确描写优先于旧记录；不按资产列表顺序猜测。**每个出镜的主要人物**须列出当前形象的原始脸部特写图和原始全身资产图，两张分别保留独立绝对路径。**每个出镜的非主要角色**只列出当前形象的原始全身资产图，不额外列其脸部特写或局部图。缺少必需资产时注明缺项，交给用户处理；不拿其他形象、先前人物插图或文字冒充。
4. 每镜可作为图片输入的参考资料严格限定为**纯场景图 + 当前形象的原始角色资产图**。不制作角色拼版、场景拼版，也不把上一镜或任何已生成的人物画面当作参考图。**不预设参考图片数量上限**，不得为了适配某个模型而删图、合图或改变角色分类；实际调用平台若有上限，在交付结果中列出完整清单并说明由用户后续处理。
5. 对武器、法宝和战斗特效，从正文、人物设定及确有该道具的原始资产提取外观与能力边界。没有明确外观时，可依据本书视觉风格设计可见形态并标注“本镜推定设计”，不得新增剧情事实、能力或命中结果。

## 设计与交付

1. 按[连续插图的逐张物料模板](prompt-template.md)在内部整理镜头顺序，再逐张交付完整物料。新场景若没有适用的纯场景图，第一镜必须规划无人场景建立图；若同地点、同时间已有适用的纯场景图，不重复设计。建立图仅呈现建筑、陈设、光源与天气，不出现人物、剪影、人群、肢体或后续才发生的破坏。后续人物镜头沿用空间结构，但独立选择机位和景别；每张提示词都须重新写出当前可见的空间、光线和人物状态，不能要求模型理解上一张。
2. 每张提示词的开头先逐一说明该张全部参考图的具体内容和用途，例如“慕星离脸部特写”“慕星离全身图”“夜晚浅洞纯场景图”；随后只描述这一瞬间的人物姿势、视线、接触关系、情绪变化、当前形象与服装边界、关键道具、场景及光线。全身镜头设计自然可执行的姿势、人物与前景物的遮挡关系及完整入画范围；不机械罗列关节。战斗镜头写明双方实际出力，特效从何处发出、经过何处、作用于何物及这一瞬的动作阶段；特效充分但不遮挡动作因果。减少无关人物、装饰、文字、水印和随机噪声。
3. 按主体和空间关系建议画幅方向与比例，不固定全书统一尺寸。正文锚点、镜头顺序、设计理由和连续性核对只供内部规划或放在物料说明中；提示词只写参考图说明与完整画面信息，不写“剧情锚点与唯一事件”“与上一镜的连续性”“上一镜”等流程语。跨镜头应继承的服装、伤势、站位、道具和场景变化，必须写成该张画面中具体可见的事实。
4. **交付前只核对设计资料**：主要人物名单是否经用户确定、剧情锚点和形象 ID 是否有依据、每镜参考图是否来自纯场景或当前角色资产、必需图片路径是否真实列出、全部镜头与提示词是否齐全。这里不检查任何生成结果。最终按模板**逐张**展示对应正文位置、该张所需**全部**实际参考图片的 Markdown 预览与可复制的绝对路径、各图具体内容和用途，以及该张可单独使用的完整提示词。重复使用的参考图也要在每张物料里重复展示；不能只给一份全局清单。最后列出尚待用户生成的场景图或缺失资产。不得声称图片已生成、已验证或已插入。

## 读取操作示例

```json
{"action":"illustration.references","input":{"chapterCardId":"从 index 取得的章节 ID","query":"夜晚洞穴","order":"desc","offset":0,"limit":6}}
```

```json
{"action":"character.assets","input":{"characterId":"从 index 取得的角色 ID"}}
```

具体调用方式见[创作工具的空间操作](../creation/workspace.md)。
