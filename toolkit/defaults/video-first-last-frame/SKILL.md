# 影视设计（首尾帧）

本工具只设计**首尾帧视频生成脚本**。用户从创作空间的小说正文中选定两张图片，并明确哪张是首帧、哪张是尾帧后，读取对应正文上下文和人物设计，交付两张图片及一段完整、可复制的视频生成提示词。

本工具不生成或修改图片，不调用视频模型，不生成成片，也不修改小说正文。它只读取创作空间并输出脚本。执行者必须能直接查看图片像素；不能看图时应说明限制并停止，不得根据文件名、编号或附近正文假装理解画面。

## 关联工具

- [创作工具的空间操作](../creation/workspace.md)：用 `index` 定位小说、卷章、正文和人物；用 `read`、`search` 读取正文；用 `illustration.references` 核对正文插图；用 `character.read`、`character.assets` 读取人物设计与当前形象。这里只使用读取操作。
- [创作工具的上下文操作](../creation/context.md)：按需读取与目标片段有关的创作约束、世界观和素材，不整库加载。
- [影视设计](../video/SKILL.md)：需要按整章划分多个场景、使用多图融合或综合设计时改用该工具。
- [首尾帧脚本模板](prompt-template.md)：最终交付字段及提示词骨架。

## 必需输入

开始前必须取得以下信息：

1. 目标小说或创作空间；
2. 正文中的两张图片，且用户明确指定**首帧**和**尾帧**；
3. 两张图片对应的剧情范围，或足以在正文中唯一定位该范围的信息。

如果用户只选了两张图但没有说明顺序，只询问“哪张是首帧、哪张是尾帧”，不要自行按文件名、编号或正文顺序猜测。若两张图不属于同一段可连续表现的剧情，应指出冲突并请用户调整选图或明确希望如何衔接。

## 工作流程

### 1. 核对图片确实来自正文

1. 用 `index` 定位目标书籍、卷、章卡和正文文件 ID；书名或章节无法唯一确定时先询问。
2. 用 `illustration.references` 读取目标章的正文插图，按 `offset` 翻页直到 `hasMore` 为 `false`。核对两张图的绝对路径、`nearbyText` 和 `available`。
3. 两张图都必须由该章正文 `body.md` 以 `![](images/文件名)` 引用，并位于该章同级 `images/` 目录。候选稿、临时交付目录、角色资产图或聊天附件不能冒充正文插图。
4. 实际打开并观察两张图片，分别记录人物、服装、姿态、场景、光线、构图、镜头角度和可见动作状态。

### 2. 读取剧情上下文

1. 用 `read` 完整读取目标章正文。通过两张图片的引用位置与附近正文确定首帧到尾帧所覆盖的剧情起止；必要时用 `search` 定位人物、对白和动作原文。
2. 至少读取首帧前后的起因、两帧之间发生的动作以及尾帧后的结果，避免只根据插图编造过渡。
3. 按需读取相邻章节、章卡、章末状态、接续包和本书创作约束；只读取解释该片段所必需的内容。
4. 明确列出片段中的出镜人物、关键道具、地点、时间、天气、伤势、服装、站位及正文原话。正文没有的动作、台词和设定不得补写成事实。

### 3. 核对人物设计

1. 对两帧及中间剧情中出现的每个人物，用 `character.read` 读取角色档案和形象记录，用 `character.assets` 核对当前形象资产。
2. 根据正文中的换装、受伤、变身和时间点确定对应 `appearanceId`，不按资产列表顺序猜测。
3. 比较正文、人物设计、首帧和尾帧中的人物外观。若图片与当前形象有差异，以两张选定图片中实际可见的外观作为本次视频的视觉锚点，并在脚本前单列差异提醒；不得悄悄改脸、换装或消除伤势。

### 4. 判断能否连续过渡

逐项比较两帧：

- 人物是否一致，服装和伤势变化是否有正文依据；
- 地点、时间、光线和天气是否可在一段视频内连续变化；
- 镜头轴线、人物站位、景别和构图变化是否能通过运镜或合理切镜连接；
- 首帧动作是否有自然的后续，尾帧状态是否是该动作链的合理落点。

存在可解释差异时，把变化写进中间时间线；存在无法解释的换人、换地点、服装突变或剧情跳跃时，不强行生成虚假连续动作，先说明具体冲突并请用户换图或确认允许的转场方式。

### 5. 设计视频脚本

1. 根据实际动作链和对白可读性确定时长，不套固定秒数。普通单动作可用 L1，多节拍或对白用 L2，战斗、变身或复杂多人交互用 L3。
2. 提示词必须从首帧可见状态开始，以尾帧可见状态准确结束：不得交换顺序，不得在尾帧之后继续新动作。
3. 按时间线写清每个动作的起因、过程和结果，以及人物表情、视线、重心、站位、道具、特效、环境反馈与镜头运动。多人物动作错峰发生，不瞬移、不跳轴。
4. 两帧之间的服装、光线、天气、伤势或构图变化必须有可见过渡。没有正文依据的变化列入严格避免项。
5. 对白只使用正文原话并标明说话者和时间点；无对白时明确写“无对白”。音频写环境声、动作拟音和必要配乐，不杜撰旁白。
6. 提示词中明确：`image 1` 是首帧，`image 2` 是尾帧；视频从 image 1 开始并准确停在 image 2。

## 交付要求

严格按 [首尾帧脚本模板](prompt-template.md) 交付，每次只处理用户选定的一对图片。必须包含：

1. 剧情范围与正文依据；
2. 首帧图片的 Markdown 预览、绝对路径和画面说明；
3. 尾帧图片的 Markdown 预览、绝对路径和画面说明；
4. 人物设计依据及可见差异；
5. 建议时长与复杂度等级；
6. 一段可单独复制使用的完整视频生成提示词；
7. 仍需用户确认的问题或首尾帧不一致风险。

首帧和尾帧必须分别设置独立小节，并明确标为 **“首帧（image 1）”**、**“尾帧（image 2）”**。每个小节都必须同时展示 Markdown 图片预览、可复制的绝对路径、图片在正文中的位置和画面说明；不能只给文件名、只给路径或只展示其中一张。

视频生成提示词必须脱离本次回答的其它段落也能独立使用：提示词内部重新说明 image 1 和 image 2 各自的画面身份，概述有正文依据的起因、变化过程和结果，写明每个出镜人物的当前形象、服装、伤势、站位与动作，并按时间线解释画面如何从首帧连续变化到尾帧。不得使用“如上图”“上述人物”“上一段”“参考前文”等依赖外部上下文的表达，也不能用本地路径代替对图片内容的说明。

路径只是资产说明。真正生成视频时，必须在视频平台分别上传首帧和尾帧，不能把本地路径写进提示词后声称图片已上传。不得声称成片已经生成或验证。

```json
{"action":"index","input":{}}
```

```json
{"action":"illustration.references","input":{"chapterCardId":"从 index 取得的章卡 ID","order":"asc","offset":0,"limit":20}}
```

{"action":"character.read","input":{"characterId":"从 index 取得的人物 ID"}}

```json
{"action":"character.assets","input":{"characterId":"从 index 取得的人物 ID"}}
```
