# 声音设计工具

本工具由外部 Agent 执行。应用内的“创建声音”只负责用户上传音频的声音克隆；没有录音或希望设计全新声线时使用本工具。工具文件位于工作目录 `tools/voice-design/`，可以在应用的“工具管理”中编辑。需要 Node.js 24+ 和 FishAudio API Key；**密钥只通过运行环境变量 `FISH_AUDIO_API_KEY` 提供**，不要写入小说、工具文件、请求 JSON 或聊天记录。应用设置中保存的密钥由系统加密，独立 CLI 不读取它。

## 关联工具

[创作工具的空间操作](../creation/workspace.md)提供 `index`、`character.read` 和 `read`。先用它找到目标角色并读取已保存资料；不得从页面截图或未保存的编辑草稿推断角色设定。

## 设计声音

1. 先确定目标书籍的绝对目录，之后每次调用 `creation` 都传入该书的 `--book`。若用户只给角色名，而工作目录中多本书都有同名角色，先请用户指定书籍，不要猜测或跨书混用资料。在已确定的书籍内调用 `index` 定位角色 ID，再用 `character.read` 取得核心档案、人物关系、当前状态和历史轨迹。只取**当前角色**相关的记录；关系、状态和历史不截断。遇到需要核对的引用，按索引用 `read` 读取对应文件。不要载入长篇主智能体配置、形象图片或整本正文。
2. 结合用户的特别要求，写一段中文声音设计提示词，明确年龄感、性别表现、口音、音色、气息、语气、说话节奏和情绪变化。设定未给出的要素可提出适合角色的设计选择，但不要写成已经确认的剧情事实。保持可听辨的声线特征，避免仅用“好听”“有磁性”等空泛形容。控制在 1800 汉字以内；不要加入标题、解释或 Markdown。
3. 将提示词展示给用户核对；若用户要求直接创建，则继续。调用下面的 CLI 创建声音。一次请求只创建一个声音，避免重复提交。创建成功后将返回的声音名称、ID 和链接交给用户，并在默认浏览器打开返回的链接。平台失败时报告具体错误，不声称已创建。

## 创建声音

从 `{"action":"schema"}` 查询 JSON 输入格式。将请求写到临时 JSON 文件或通过 stdin 传入，不在命令行参数中携带密钥：

```sh
node /工作目录/tools/voice-design/cli.mjs --input /请求.json
```

请求示例：

```json
{"action":"create","input":{"title":"角色名称的声音","instruction":"声音设计提示词"}}
```

CLI 调用 FishAudio 声音设计接口生成样本，再把样本创建为私有声音，返回 `{ "id", "title", "url" }`。不在本地保存声音或角色数据。`FISH_AUDIO_API_KEY` 未配置时应先让用户在外部 Agent 运行环境中配置；应用里的密钥不会自动共享给 CLI。
