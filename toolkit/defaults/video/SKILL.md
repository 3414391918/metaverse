# 视频工具

本工具由**能直接查看并理解图片**的外部 Agent 执行。输入是首帧和尾帧图片的两个绝对路径；交付物是可供视频模型使用的完整脚本、首尾帧文件清单和生成提示词。**当前不调用视频模型、不生成或插入视频。**不能用文件名、图像元数据或正文描述代替实际看图。

## 关联工具

- [创作工具的空间操作](../creation/workspace.md)：用 `index`、`read`、`search`、`character.read`、`character.assets`、`illustration.references` 查本书资料。调用时始终传入同一本书的绝对目录 `--book`。
- [创作工具的上下文操作](../creation/context.md)：仅在相关时读取本书规则、技能和素材，不整库加载。
- [自定义风格预设模板](style-presets.md)：每次根据小说正文、现有插图及两帧实际视觉现场填写，不预先固定风格。
- [视频脚本与提示词骨架](prompt-template.md)：按剧情复杂度选 L1/L2/L3，完成组装、交付及迭代。

## 输入与证据定位

1. 确认两条路径是可读取的本地**绝对路径**，标记首帧、尾帧及先后顺序。用当前可用的视觉能力**实际打开并观察两张图片**，逐张记录人物与当前形象、表情、姿态、手持物、站位、镜头、场景布局、光线、已发生的变化。把“图中可见”与“根据正文推断”分开写。不能看图时停止并说明缺少视觉能力；不能假装已经理解图片。
2. 从路径推断候选书籍与章节，但不靠文件名或图片编号确定剧情先后。若图片属于工作目录中的小说，用 `index` 找到相应章节；再以 `illustration.references` 比对**完整绝对路径**和正文引用、附近文本。图片可能插在随意位置，附近文字只作线索，不能直接等同于图片所描绘的时刻。路径在书外或多个书籍都能匹配时，结合用户提供的书名定位；仍无法唯一确定本书才询问用户。
3. 用 `read` 完整读取候选章正文和必要的相邻章节、章卡、章末状态与接续包；用 `search` 追查两帧中辨认的场景、角色、道具和动作。给每帧找出最有依据的正文锚点：章节、情节起止、具体句段及匹配理由。必要时读取 `character.read` 和 `character.assets`，核对角色身份、当前形象及前后是否换装、受伤或变身。角色、场景图和旧章节有冲突时，以该剧情时刻明确的正文与角色设定为准，并在脚本中说明未解冲突。
4. **先确定两帧之间实际发生了什么，再设计镜头。**按正文时间顺序列出动作、因果、角色反应、情绪变化、对话、场景和状态变化；对每个节拍注明正文依据。区分正文明确发生、图片可见但正文未写明、以及为连接两帧所做的保守推断。图片插入点、编号相邻或构图相似都不足以证明两个事件连续。若两帧不属于同一可衔接情节、先后颠倒、关键内容无法从正文判定，先给出定位结果和缺口，请用户补充或更换帧，不凭空编一段剧情。

## 自动设计参数

- **复杂度**：Agent 根据两帧之间的动作链、角色交互、空间变化、对白与连续性风险，自行选 L1 精简、L2 分镜或 L3 精细动作；参考 [提示词骨架](prompt-template.md)。不要为了采用 L3 堆积无关模块。
- **输入模态**：固定为“首帧 + 尾帧图生视频”。脚本明确首帧从第一张图片起、最后精确落在第二张图片；两张图是视觉锚点，文本着重写图中看不出的运动、时间、因果、运镜和声音。若首尾场景确有变化，就按剧情描述变化，不能套用“环境始终不变”。
- **风格**：阅读小说语言、时代、场景及现有插图，按 [自定义预设模板](style-presets.md) 现场填写定义、色调、视觉权重、必须做、禁止做、典型应用。风格选择需解释依据；不让风格覆盖角色资产和首尾帧事实。当前工具只为本次脚本使用该预设，不自动改写预设文件。
- **时长**：由必需的动作和对白的可读性推算，给出目标秒数及节拍分配理由；不设统一秒数，也不以压缩剧情为代价。若跨度过大，输出可衔接的多个片段及其各自首尾状态；只有用户提供的两张图能作为整组起点和终点，中间帧须标注为待生成，不得伪称已有文件。
- **音频**：默认平台原生音频，按时间线写环境音、动作拟音、必要配乐与对白。对白只取小说中相关人物的原话，标明说话者和正文出处；不能杜撰台词。没有小说对白就写无对白，不为凑声音添加话语。不要询问目标平台，也不依赖平台时长或音频能力列表。
- **输出语言**：由小说及用户语境自行判断，通常与正文语言一致；角色台词保留正文原文。无需问角色数量、作品段数与位置、目标 AI 平台或输出语言。

## 组装、交付、迭代

1. 先完成“首尾帧观察 → 正文锚点 → 中间剧情节拍 → 自定义风格 → 时长与复杂度”的取材记录，再套用 [提示词骨架](prompt-template.md) 生成可直接交给视频模型的完整提示词。提示词逐镜写时间、景别/机位、动作因果、表情变化、运镜、光影、场景状态、音效和对白。每个镜头以一个主要事件为中心；复杂打斗需要连续的发力、反应、招式与特效结果，不能瞬移或把先后动作叠在同一瞬间。
2. 锁定人物脸、服装、道具、站位、朝向及场景结构；只允许正文支持的状态变化。图片已表达的静态外观可简写，重点交代运动和变化。首镜明确从首帧图片开始，末镜明确停在尾帧图片的构图与状态；两帧在人物、服装或场景上不一致时，需要在中间节拍解释其变化。
3. 交付时**展示或附带首尾帧原图**（支持本地 Markdown 图片时用绝对路径嵌入），并给出两张图片的完整绝对路径和首尾用途；还要给出定位到的书、章节及文本证据，“图中可见／正文明确／连接推断”的简短对照，自定义风格预设，选定等级、时长和理由，按时间顺序的视频脚本，完整可复制的模型提示词，以及可调整项。路径只是资产清单，**不能把本地路径写进文字提示词就声称视频模型已收到图**；执行者须在所选视频工具里真正上传或附上两张图。
4. 用户提供视频结果或指出问题后，针对性修改对应段落：脸或服装漂移改角色锚点，动作断裂改因果链，首尾帧偏离改开头/结尾及过渡，节奏过急改时长和镜头分配，音画不合改对白与拟音时间。保留有正文依据的剧情事实与两张首尾帧，不因一次失败重写故事。
