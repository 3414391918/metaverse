# 影视设计

本工具只负责**生成前的视频脚本设计**。用户给出小说的卷章，或只指定其中一段剧情（含“为以上内容生成视频生成脚本”这类承接上文的请求），按正文剧情拆分场景并逐段交付可直接使用的视频生成脚本：脚本形式、时长、全部参考图的预览与绝对路径，以及完整的视频生成提示词。每段都以本场景纯场景图加该段全部出镜人物的角色资产图控制一致性。**本工具不调用视频模型，不生成、插入或审核视频；成片质量由用户自行验证。**

本工具由**能直接查看并理解图片**的外部 Agent 执行。参考图必须实际打开观察，不能用文件名、附近正文或图片编号代替看图。不具备视觉能力时停止并说明，不得假装已理解图片。

## 关联工具

- [创作工具的空间操作](../creation/workspace.md)：用 `index` 定位卷、章卡与正文文件；用 `read`、`search` 读取剧情；用 `illustration.references` 查该章已入正文的插图；用 `character.read`、`character.assets` 读取当前形象与原始角色资产。这里只使用读取操作。
- [创作工具的上下文操作](../creation/context.md)：按需读取本书约束、相关技能与素材，不整库加载。
- [插图设计](../illustration/SKILL.md)：本工具所依赖的纯场景图与插图由该工具设计；缺图时请用户先在那里补做。
- [按场景分段的脚本交付模板](prompt-template.md)：三类脚本形式的字段、分级与交付结构。
- [自定义风格预设模板](style-presets.md)：每个场景依据正文和本章实际插图现场填写，不预设固定风格。

## 输入与剧情定位

1. 用户可能指定整章，也可能只指定其中一段内容：
   - **整章**：例如“帮我生成《万象诸界》第一卷第六章的视频生成脚本”。用 `index` 读取该书索引，按**卷序与卷内章序**定位章卡，拿到正文文件 ID。
   - **章内片段**：例如“为以上内容生成视频生成脚本”或贴出一段正文。从**当前对话上下文**识别用户指的是哪段剧情：上文刚讨论或刚贴出的正文、刚完成的插图设计都是线索。再用 `search` 在正文中找到这段的**实际起止位置**并读取原文，以正文为准，不凭对话中的摘述代替原文。
   - 两种情形下，书名、卷章或片段边界无法唯一确定时询问用户，并先说明自己当前判定的范围；不靠文件名或图片编号推断。开始设计前向用户回报本次覆盖的剧情起止。
2. 用 `read` 完整读取目标章正文（只做片段时也要读完整章以明确上下文），必要时读相邻章节、章卡、章末状态与接续包，掌握本章在全书中的位置。用[上下文操作](../creation/context.md)读取本书创作约束与世界观、势力、境界等与本章相关的设定；不整库加载。
3. 按正文列出目标剧情中**全部出镜人物**，并在逐段设计前请用户明确本轮哪些是主要人物，等待回复后再继续；用户已在本轮给出名单时直接采用。对每个出镜人物调用 `character.read` 与 `character.assets`，结合正文中的换装、受伤与形态变化，逐场景确定当前 `appearanceId`。正文明确描写优先于旧记录，不按资产列表顺序猜测。
4. 用 `illustration.references` 读取该章已入正文的全部插图：优先用 `query` 按地点、时段或文件名筛选，按 `offset` 翻页直到 `hasMore` 为 `false`。**即使只做章内片段，也要读全章插图清单**，因为适用的纯场景图可能插在片段之外。完整读取 `path`、`nearbyText`、`available`。**不得用 `head` 截断 JSON 输出**，也不得把首批未出现的图片判成不存在。只有**本章 `body.md` 中 `![](images/文件名)` 引用且位于同级 `images/` 目录**的文件才算正文插图；临时交付目录、候选稿目录不是图片来源。

## 场景划分

1. **场景边界以正文剧情为准，不按纯场景图在正文中的插入位置划分。** 插图的实际插入点常与对应剧情有出入，`nearbyText` 只是线索。先通读目标剧情，按**地点、时间、环境的实际转换**切分场景：人物转移到新地点、时间推进到另一时段、或环境发生明显改变时即另起一个场景。记录每个场景在正文中的起止段落。
2. 同一地点的**白天与夜晚属于不同场景**；光源、天气或场景结构发生明显变化（如起火、坍塌、换至室内）时同样另起场景。
3. 划完场景后，再为每个场景在全章插图中**按内容匹配**对应的无人纯场景图：逐一打开候选图，确认其确实无人物，并按**画面中的地点、时段、光源与场景结构**与该场景比对。图片编号顺序、插入位置和附近文字都不足以证明归属；一张图可能插在其所表现场景之前或之后，甚至在片段范围之外。同地点同时段的场景图可在多个场景重复使用。
4. 某个场景在全章插图中找不到内容相符的纯场景图时，**停下并提醒用户先为该段内容设计纯场景图**，明确指出章节、段落位置与所需时段（例如“第六章 浅洞夜间需要一张无人纯场景图”）。不得虚构路径、不得拿人物插图或其它地点、其它时段的图片顶替，也不得跳过该段直接出脚本。
5. 场景内按剧情节拍再分段：每段只承载一个可连续拍摄的动作链。剧情多的场景分多段，剧情少的场景可只有一段。分段依据机位、景别、运镜和因果变化，不按固定秒数切分；避免一段内塞入多个互不衔接的事件或跨越大段时间。

## 脚本形式选择

**默认使用多图融合。** 只有在该段确实存在一对高一致性插图时，才可改用首尾帧。**不提供单图参考**：只给一张插图无法约束画面中其他人物的长相与服装，脚本一旦写到该图中不存在的人物，一致性就无从保证。

| 形式 | 适用情形 | 参考图要求 |
| --- | --- | --- |
| 多图融合（默认） | 容错率最高，适用于绝大多数段落 | **必须**包含本场景纯场景图，以及该段出镜的**每一个**人物当前形象的原始角色资产图；正文插图按需补充姿态或氛围参考 |
| 首尾帧 | 最稳定，但要求两张插图的人物、服装、机位与画面风格一致性足够高 | 两张已入正文的插图作首帧与尾帧，顺序明确；**同时附上本场景纯场景图与该段全部出镜人物的原始角色资产图** |

- **参考图必须覆盖该段出现的每一个人物。** 先按正文列出本段出镜名单，再逐人备齐资产图。脚本中不得出现参考图未覆盖的人物；确需出现时，先补该角色的资产图，或改写该段避开他。
- **在逐段设计前，请用户明确本轮哪些是主要人物，并等待回复。** 主要人物由用户决定，不按主角身份、戏份或画面大小自行划定；用户在本轮已给出名单时直接采用，不重复询问。未列入名单的出镜者视为非主要角色。
- **主要人物**列出当前形象的原始脸部特写图和原始全身资产图，两张分别保留独立绝对路径；**非主要角色**只列当前形象的原始全身资产图。不制作角色拼版或场景拼版，不把已生成的视频帧当作参考图。
- **首尾帧需要 Agent 实际比对两张插图的质量与一致性后再决定**：人物形象、服装、光线或构图差异过大时回到多图融合，不为追求稳定硬凑。
- **不预设参考图数量上限**；实际平台若有限制，在交付中列出完整清单并说明由用户后续处理。
- 参考图缺失时注明缺项并交给用户处理，不拿其它形象、其它角色或文字冒充。

## 设计参数

- **时长**：由该段必需的动作与对白可读性推算，给出秒数及节拍分配理由；不设统一秒数，也不以压缩剧情为代价。
- **复杂度**：按该段动作链、角色交互与空间变化自行选 L1/L2/L3，见[交付模板](prompt-template.md)；不为用上 L3 堆砌无关模块。
- **风格**：依据正文与本章实际插图，按[自定义预设模板](style-presets.md)现场填写并说明依据；风格不得覆盖角色资产与正文事实。
- **音频**：默认平台原生音频，按时间线写环境音、动作拟音与必要配乐。对白只取正文原话并标明说话者与出处，没有对白就写明无对白，不杜撰台词。
- **输出语言**：与正文语言一致，角色台词保留原文。不询问目标平台、作品段数或输出语言。

## 交付

1. 按[交付模板](prompt-template.md)组织内容。**每次只交付一个场景下的全部视频脚本**，交付后等待用户确认再继续下一个场景；不要一次倒出全部场景。开头说明本次覆盖的剧情范围（整章或指定片段）、本场景在该范围中的位置、总场景数与当前进度。
2. 每个脚本必须包含四项：**脚本形式**（多图融合／首尾帧及选择理由）、**时长**、**全部参考图片**（逐张给出 Markdown 预览、可复制的绝对路径，以及该图的具体内容与用途）、**完整的视频生成提示词**。重复使用的参考图在每个脚本中重复展示，不能只给一份全局清单。
3. 提示词开头先逐一说明每张参考图的内容与用途，例如“慕星离脸部特写”“夜晚浅洞纯场景图”；随后只描述这一段的运动、因果、表情变化、光影与声音。提示词须可单独使用：不写“上一段”“与前镜的连续性”等流程语，跨段应继承的服装、伤势、站位与场景变化写成画面中可见的事实。
4. 战斗段落写明双方实际出力、招式起止、特效从何处发出经过何处作用于何物，以及这一段的动作阶段；不把先后动作压在同一瞬间，也不瞬移或瞬间完成特效。
5. **交付前核对每个脚本的参考图是否覆盖该段全部出镜人物**，以及主要人物是否都有脸部特写加全身图、非主要角色是否有全身图、本场景纯场景图是否在列。有缺口就补图或标为待用户处理，不得带着缺口出脚本。
6. 路径只是资产清单。**不能把本地路径写进文字提示词就声称视频模型已收到图**；执行者须在所选视频工具里真正上传这些图片。交付末尾列出本场景尚缺的纯场景图或角色资产。不得声称视频已生成或已验证。
7. 用户反馈成片问题后只改失效部分：形象漂移改角色锚点与参考图，动作断裂改因果链与时间线，首尾不符改首末帧锚定，节奏问题改时长与分段，音画不合改对白与拟音时点。保留有正文依据的剧情事实。

